# 任务大厅小程序（骨架版 v0.1.0）

微信小程序 + 微信云开发。核心业务：**发布任务 → 他人接单 → 完成确认**，任务可带定位、可评论，另有独立的大厅交流区。

当前是**最小可运行骨架**：页面、路由、云函数、数据模型全部打通，业务流程能跑通主链路，但只做了骨架级实现（详见 `docs/TODO.md`）。

---

## 一、技术选型与理由

| 项 | 选择 | 理由 |
|---|---|---|
| 前端 | 微信原生小程序（WXML/WXSS/JS） | 不引构建链，开发者工具直接打开就能跑 |
| 后端 | 微信云开发（云函数 + 云数据库） | 零服务器、零域名备案、零 HTTPS 证书；月成本约 20-30 元 |
| 定位 | 微信 `chooseLocation` + 云数据库 `Geo.Point` | 原生能力，无需第三方地图 SDK 和 Key |
| 状态流转 | 云数据库 `where({_id, status})` 条件更新 | 单文档原子性天然防并发抢单，不需要分布式锁 |

不选 Spring Boot 的原因：这个需求的量级用不上，反而多出服务器、备案、运维三笔成本。真到要分账、要复杂结算时再迁移（迁移路径见 TODO P2-4）。

**分层约定（别破坏它）：**
- `pages` 只管状态和交互，不写业务判断
- `services` 只管调云函数和字段装饰，不做校验
- `cloudfunctions` 是唯一权威：所有校验、权限、状态流转都在这里，前端说啥都不算数
- `utils` 是无副作用的纯函数层

## 三、核心设计

### 1. 任务状态机

```
pending(待接单) --grab--> accepted(进行中) --submit--> confirming(待确认) --confirm--> completed(已完成)
     |
     +--cancel--> cancelled(已取消)
```

每条流转都在云函数里用 `where({_id, status: 期望值}).update(...)` 实现，`stats.updated !== 1` 就直接报 `STATUS_CONFLICT`。两人同时抢同一单，只有一个人能拿到。

### 2. 评论两级结构

`comments` 集合用 `parentId` 区分层级：`parentId === ''` 是主楼，非空是回复，且**父级必须是主楼**（云函数强制校验）。微信小程序的评论超过两级没人看得懂，故意做成两级。

任务评论和大厅回复共用这套结构，靠 `targetType` 区分（`task` / `hall`）。

### 3. 权限由服务端下发

`task.detail` 返回 `permissions` 对象，页面只根据它决定显示哪些按钮：

```
canGrab / canSubmit / canConfirm / canCancel / canViewContact
```

`contact`（联系方式）在列表页根本不返回，详情页只对发布者和接单者返回。前端即使改代码也拿不到别人的联系方式。

> ⚠️ 注意区分两类权限：**内容级权限**（谁是 owner / taker）已实现；**身份级权限**（未登录拦截、封禁、资料不全）目前只做了 `openid` 存在性校验，规则见 `docs/auth-rules.md`，尚未按规则落地。

### 4. emoji 表情输入

说明见 `docs/emoji.md`。要点：

- **用 Unicode 原生 emoji，不引图片**。200 个表情以字符串常量存储，整体只增加 8.2 KB，iOS/Android 都渲染成系统彩色表情。
- **输入条抽成 `comment-bar` 组件**，任务评论和话题回复共用一份，改逻辑只改一处。
- **光标位置用 `wx.getSelectedTextRange()` 读，但必须在失焦前读**——点输入框以外区域时系统会先失焦再派发 tap，所以接了 5 个捕获点：😀 按钮的 `touchstart`（主路径）、input 的 `tap`、`focus`、聚焦期 400ms 轮询、`bindinput`。`bindinput` 单独用不够，它只在内容变化时给位置。
- **键盘遮挡自己接管**：`adjust-position=false` + 监听 `bindkeyboardheightchange`，按「视口有没有被压缩」区分 iOS（需要上移键盘高度）和 Android（不能叠加，否则会飘）。
- **字数按码点算**，`Array.from(str).length`，一个表情记 1 个字，不是 2 个。
- **删除按代理对判断**，emoji 一次整个删掉，不会剩半个字符变乱码。

## 四、快速启动（照这个顺序做）

### 步骤 1：换 AppID
打开 `project.config.json`，把 `"appid": "touristappid"` 换成你自己的小程序 AppID。
> **云开发不支持测试号/游客模式**，必须是有 AppID 的正式小程序账号。

### 步骤 2：导入项目
微信开发者工具 → 导入项目 → 选择 `task-hall-miniprogram` 目录（不是里面的 miniprogram 目录）。

### 步骤 3：开通云开发
工具栏点「云开发」→ 开通 → 新建环境（免费额度够开发用）。
记下环境 ID，如果有多个环境，把 ID 填到 `miniprogram/config/index.js` 的 `envId`；只有一个环境就留空，会自动用当前默认环境。

### 步骤 4：部署 5 个云函数

`cloudfunctions` 目录 → 右键每个函数目录 → **上传并部署：云端安装依赖（不上传 node_modules）**。
五个都要传：`login`、`task`、`comment`、`post`、`initdb`。
注意右键的是**函数文件夹**，不是里面的 `index.js`。

> ✅ **已完成**（2026-11-08）环境 ID：`<你的云环境ID>`，5 个函数均已部署成功。
>
> 以后改了云函数代码，不用再右键五次，一条命令批量更新：
> ```bash
> "D:\微信web开发者工具\cli.bat" cloud functions deploy \
>   --env <你的云环境ID> \
>   --names login task comment post initdb \
>   --project "C:/Users/99541/WorkBuddy/2026-11-07-23-16-00/task-hall-miniprogram" \
>   --remote-npm-install true
> ```
> 前提：开发者工具 → 设置 → 安全设置 → **服务端口** 已打开。

### 步骤 5：初始化数据库
云开发控制台 → 云函数 → `initdb` → 云端测试 → 入参填：
```json
{ "seed": true }
```
返回 `collections` 里四个集合都是 `created` 或 `exists` 即成功，`seeded` 会带一条示例任务和一条示例话题的 id。

> **这一步可以跳过。** 每个写操作都有 `addWithColl` 兜底——集合不存在时自动创建。跳过只意味着首页没有示例数据，你自己发一条任务效果一样。
> 命令行工具没有「调用云函数」的能力，`initdb` 只能在控制台点「云端测试」触发。

### 步骤 6：建索引（影响性能，建议做）

云开发控制台 → 数据库 → 左侧选集合 → 右侧「**索引管理**」页签 → 「**+ 添加索引**」。

弹窗里三样东西：索引名称（自己起）、索引属性（唯一 / 非唯一）、索引字段（字段名 + 升序/降序，可加多个）。

**索引字段的顺序很重要**：等值查询的字段放前面，排序字段放最后。顺序错了索引就白建。

| 集合 | 索引名 | 字段顺序 | 属性 | 服务于哪个查询 |
|---|---|---|---|---|
| `tasks` | `idx_status_created` | `status` 升序 → `createdAt` 降序 | 非唯一 | 任务大厅按状态筛选 + 时间倒序 |
| `tasks` | `idx_owner` | `ownerOpenid` 升序 → `createdAt` 降序 | 非唯一 | 我的任务「我发布的」 |
| `tasks` | `idx_taker` | `takerOpenid` 升序 → `createdAt` 降序 | 非唯一 | 我的任务「我接的单」 |
| `comments` | `idx_target` | `targetType` 升序 → `targetId` 升序 → `parentId` 升序 → `createdAt` 降序 | 非唯一 | 评论分页 + 取某条主楼下的回复 |
| `posts` | `idx_created` | `createdAt` 降序 | 非唯一 | 大厅话题流 |
| `users` | `uniq_openid` | `openid` 升序 | **唯一** | 按 openid 查用户；唯一可防重复建档 |

几点提醒：

- **字段名大小写必须和文档完全一致**（`targetType`、`ownerOpenid`），写错不会报错，只是索引不生效。
- **唯一索引在已有重复数据时会创建失败**。`users.openid` 在建之前先确认没有重复；我们的 `ensureUser` 是「查不到才建」，正常不会重复。
- **索引不是越多越好**，每个索引都占空间、拖慢写入。上面 6 个是够用的上限，别再额外加。
- **`geo` 字段的地理索引**当前控制台没有 2dsphere 入口，先跳过。这个索引只在 P1-2 切换成 `geoNear` 检索时才需要，现在用的是内存排序。
- 建完状态会自动从「构建中」变成正常，小数据量秒级完成。`命中次数` 一开始是 0，正常——用起来才会累加。

> ✅ **已完成**（2026-11-08）：上表 6 个索引均已建好并核对通过（字段顺序、升降序、唯一属性全部正确）。

### 步骤 7：设置集合权限
四个集合统一设为 **「所有用户可读，仅创建者可写」**。
写操作走云函数，云函数有管理员权限，不受这条限制；这样即使有人反编译小程序，也改不了别人的数据。

## 六、常见问题

**1. Console 报「云函数 xxx 调用失败，请确认已部署」**
云函数没上传，或上传时选了「上传并部署：所有文件」但没装依赖。重新选「云端安装依赖」。

**2. 点选地点报「选点失败，请检查是否已开通位置权限」**
小程序后台 → 开发管理 → 接口设置 → 申请「地理位置」→ 开通 `wx.getLocation` 和 `wx.chooseLocation`。
`app.json` 里已声明 `requiredPrivateInfos`，但后台没开通接口依然会被拦。

**3. 数据一直空，但没报错**
`config/index.js` 的 `envId` 指向了错误环境，或者数据写到了另一个环境。留空用默认环境最稳。

**4. 「手慢了，任务已被别人抢走」**
这就是并发保护生效了，不是 bug。

**5. 上传云函数报体积超限**
忘了选「云端安装依赖」，把 node_modules 传上去了。
