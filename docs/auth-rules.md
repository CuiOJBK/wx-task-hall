# 权限与注册机制规则 v1.1

> 适用范围：任务大厅小程序全站（`miniprogram/` + `cloudfunctions/`）
> 文档性质：**规则与校验要求**，不含实现代码。落地时按此逐条对照。
> 编写日期：2026-11-08　最后修订：2026-11-08（v1.1 调整匿名浏览边界）

---

## 0. 前提事实（读规则前必须接受的三个事实）

**F1　微信小程序下不存在「拿不到身份」的情况。**
每次云函数调用都会由微信侧注入 `OPENID`，服务端永远知道「这是哪个微信用户」。所以「匿名」不是技术上的身份缺失，而是**业务上该用户尚未完成授权建档，或档案状态异常**。当前实现里 `if (!OPENID) return FORBIDDEN` 这条校验在真实环境中几乎永不触发，属于无效防线。

**F2　前端判断一律不可信，但必须做。**
小程序包可被解包、云函数可被直接 HTTP 调用伪造入参。所以规则必须写成两层：前端拦截负责**体验与引导**，服务端校验负责**安全**。两者判定条件必须一致，且服务端不依赖前端任何字段。

**F3　匿名采用「半开放浏览」，不放行也不全封。**
匿名用户可浏览**任务大厅列表的前 10 条摘要**，但不得查看任务内容、不得翻页、不得搜索、不得进行任何互动。因此拦截点不在首页，而在「点击任务 / 切换筛选 / 任何写操作」三处。按微信审核要求仍需：① 在首位任务上方或登录引导处一句话说明用途；② 登录引导必须可由用户主动关闭；③ 不得在用户点击前静默调用用户信息接口。

## 一、权限规则

### 1.1 身份定义（三分类）

| 身份 | 判定条件（服务端） | 说明 |
|---|---|---|
| **匿名 / 未授权** | 无用户档案记录；或档案存在但 `authStatus = unauthorized` | 未点击过「微信一键登录」，或主动退出了本地会话 |
| **已登录** | 档案存在且 `status = active` | 唯一可执行业务操作的身份 |
| **受限 / 异常** | 档案存在且 `status ∈ {banned, disabled}`；或 `profileComplete = false` | 身份可识别但不可操作 |

`status` 与 `profileComplete` 是**两个独立维度**：
- `status` 决定「能不能用」（封禁/停用）
- `profileComplete` 决定「能不能写」（发内容前必须有昵称头像）

### 1.2 权限矩阵（功能 × 身份）

| 功能 | 匿名 | 已登录（资料完整） | 已登录（资料不全） | 受限 |
|---|:--:|:--:|:--:|:--:|
| 任务大厅列表（前 10 条摘要） | ⚠️ 受限 | ✅ | ✅ | ❌ |
| 任务详情 | ❌ | ✅ | ✅ | ❌ |
| 大厅话题列表 / 话题详情 | ❌ | ✅ | ✅ | ❌ |
| 评论列表 | ❌ | ✅ | ✅ | ❌ |
| 搜索 / 关键词筛选 | ❌ | ✅ | ✅ | ❌ |
| 发布任务 | ❌ | ✅ | ❌ | ❌ |
| 接单 / 提交 / 确认 / 取消 | ❌ | ✅ | ❌ | ❌ |
| 发表评论 / 回复 | ❌ | ✅ | ❌ | ❌ |
| 发表话题 | ❌ | ✅ | ❌ | ❌ |
| 点赞（预留） | ❌ | ✅ | ❌ | ❌ |
| 删除自己的内容 | ❌ | ✅ | ❌ | ❌ |
| 查看「我的任务」 | ❌ | ✅ | ✅ | ❌ |
| 修改昵称头像 | ❌ | ✅ | ✅ | ❌ |
| 举报 | ❌ | ✅ | ✅ | ❌ |

**唯一放行项是「任务大厅列表」，且是受限放行**——详见 1.2.1。除该项外，匿名不得读取任何内容。

### 1.2.1 匿名浏览任务大厅的边界（六条硬限制）

| 编号 | 限制 | 具体要求 |
|---|---|---|
| **L1** | 条数固定 10 条 | 最多返回 10 条，忽略 `page` / `pageSize` 入参，`hasMore` 恒为 `false`，不提供翻页入口 |
| **L2** | 排序固定 | 按创建时间倒序取最新的 10 条，不接受自定义排序 |
| **L3** | 状态固定 | 仅返回 `status = pending`（待接单）。切到「进行中 / 已完成」等其它 Tab 需要登录 |
| **L4** | 字段白名单 | 只返回：任务 ID、标题、赏金、**地址区划（城市/区县）**、创建时间、状态、评论数。**不返回**描述正文、联系方式、发布者 openid、发布者昵称、地点名称、详细地址、经纬度、距离 |
| **L5** | 禁用搜索 | 匿名请求带 `keyword` 时必须忽略该参数；前端不展示搜索框。防止用关键词枚举全量数据 |
| **L6** | 不可跳详情 | 点击任一列表项 → 触发登录引导，不发起 `task.detail` 请求 |

**设计意图**：让匿名用户看到「这里有活、有人在发任务」，产生登录动机；但看不到任何任务的具体内容，也拿不到可枚举的数据（10 条 + 固定排序 + 禁搜索 + 禁翻页，信息量恒定）。

### 1.2.2 地址脱敏规则

地址是位置隐私的核心，匿名状态下按「区划可见、细节全隐」处理。

**字段范围**

| 字段 | 含义 | 匿名 | 登录 |
|---|---|:--:|:--:|
| `location.region.regionText` | 城市+区县，如「深圳市南山区」 | ✅ 展示 | ✅ |
| `location.region.province / city / district` | 分级区划 | ❌ 不下发 | ✅ |
| `location.name` | 地点名，如「菜鸟驿站（科技园店）」 | ❌ 不下发 | ✅ |
| `location.address` | 完整地址，含街道门牌 | ❌ 不下发 | ✅ |
| `location.latitude / longitude` | 经纬度 | ❌ 不下发 | ✅ |
| `distance` | 客户端算出的距离 | ❌ 不下发（可由距离反推位置） | ✅ |

**展示效果**

| 身份 | 卡片上的地址栏 |
|---|---|
| 匿名 | `📍 深圳市南山区`（解析不出区划时显示 `📍 地址已隐藏`） |
| 登录 | `📍 菜鸟驿站（科技园店） · 广东省深圳市南山区科技南十路8号` |

**实现要点**

1. 发布任务时就用正则从 `address` 解析出 `region` 落库，匿名请求直接读，不在请求期跑正则。
2. 老数据没有 `region` 字段，读取时按 `address` 现算，无需数据迁移。
3. 脱敏在**服务端**完成（`pickAnonTask` → `maskLocation`），前端 `decorateTask` 再按 `anonymous` 兜一层：即使接口意外返回完整地址，界面也只会显示「地址已隐藏」。
4. 详情页对匿名整体不可达（登录守卫），地址自然不会暴露——比「渲染后遮罩」更彻底。

### 1.3 五条硬规则

| 编号 | 规则 | 违反后果 |
|---|---|---|
| **R1** | 默认拒绝。任何未在规则中明确放行的操作，一律拒绝。 | — |
| **R2** | 身份裁决只在服务端。前端所有 `openid`、`status`、`isOwner` 字段仅用于渲染，不得作为授权依据。 | 解包后可直接调接口 |
| **R3** | 身份判定必须**同时**校验 openid 与档案状态，缺一不可。只校验 openid 等于没校验。 | 封禁用户仍可操作 |
| **R4** | 身份权限与内容权限分离。已登录 ≠ 可改所有内容；删除/修改必须校验归属（owner）。 | 越权删他人内容 |
| **R5** | 状态变更即时生效。受限用户的下一次请求必须被拒，不得依赖前端缓存的登录态。 | 封禁后仍能发帖 |
| **R6** | 业务写操作要求 `profileComplete = true`。只读不要求。 | 匿名发内容 |

### 1.4 会话规则

- 登录态来源：服务端 `login` 接口下发，包含 `openid` + 档案快照。
- 本地只缓存**展示用**信息，**不得**缓存任何权限判定结果。
- 每次冷启动、以及每次从后台切回前台，必须重新校验一次档案状态。
- 任意接口返回「受限」类错误码时，前端必须立即清除本地登录态并跳转受限页，不得继续使用旧缓存。

## 二、用户状态流转

### 2.1 状态定义

| 编号 | 状态 | 含义 | 可否访问业务页 |
|---|---|---|---|
| S0 | `UNREGISTERED` 未授权 | 首次进入，未点击登录 | ⚠️ 仅任务大厅（列表前 10 条摘要）+ 登录引导 |
| S1 | `AUTHORIZING` 授权中 | 已点击登录，服务端建档未返回 | ⏳ 加载态，阻断操作 |
| S2 | `ACTIVE` 已登录 | 建档完成，状态正常，资料完整 | ✅ 全部 |
| S3 | `INCOMPLETE` 资料不全 | 已登录但缺昵称/头像 | ⚠️ 只读 + 资料完善页 |
| S4 | `RESTRICTED` 受限 | 被封禁 / 停用 / 风控 | ❌ 仅受限说明页 |
| S5 | `SIGNED_OUT` 已退出 | 用户主动退出，本地态清空 | ❌ 回到 S0 |
| S6 | `SYSTEM_ERROR` 系统异常 | 云环境不可用 / 网络失败 | ⚠️ 错误页 + 重试 |

### 2.2 流转规则

```
                    ┌──────────────────────────────┐
                    │                              │
 冷启动 ──▶ S0 未授权 ──[点击微信一键登录]──▶ S1 授权中
                    ▲                              │
                    │                    ┌─────────┴─────────┐
                    │                 成功                 失败
                    │                    │                   │
                    │                    ▼                   ▼
                    │         ┌── 资料完整？──┐        S0（提示后停留）
                    │         │               │
                    │        是│               │否
                    │         ▼               ▼
                    │      S2 已登录      S3 资料不全 ──[完善资料]──▶ S2
                    │         │                │
                    │         │                └──[放弃]──▶ S0
                    │         │
                    │    [被后台处置]                    [主动退出]
                    │         ▼                            ▼
                    └──── S4 受限 ◀──[申诉驳回]      S5 已退出 ──▶ S0
                              │
                              └──[申诉通过]──▶ S2

  任意状态 ──[云环境/网络不可用]──▶ S6 系统异常 ──[重试成功]──▶ 回到原状态
```

### 2.3 各状态可访问页面与可执行操作

| 状态 | 可访问页面 | 可执行操作 | 禁止 |
|---|---|---|---|
| **S0 未授权** | 任务大厅（仅列表前 10 条摘要）、登录引导页、隐私协议页 | 浏览大厅列表、点击登录、查看协议、退出小程序 | 查看任务详情、切换大厅筛选 Tab、搜索、翻页，以及一切互动 |
| **S1 授权中** | 登录引导页（loading） | 取消 | 一切业务操作，防重复提交 |
| **S2 已登录** | 全部 7 个页面 | 全部业务操作（受内容级权限约束） | — |
| **S3 资料不全** | 任务大厅、详情、话题、我的任务、我的（资料页） | 浏览、完善资料 | 发布、接单、评论、发帖、点赞、删除 |
| **S4 受限** | 受限说明页、申诉入口（预留） | 查看原因、申诉、退出 | 一切业务操作 |
| **S5 已退出** | 同 S0 | 重新登录 | 同 S0 |
| **S6 系统异常** | 错误页 | 重试、退出 | 一切依赖云函数的操作 |

**页面级拦截要求**：无论是 tabBar 切换、`navigateTo`、扫码直达、分享卡片进入，都必须走同一条拦截逻辑。**分享链接不得绕过登录**——落地到任务详情页时，S0 状态必须先弹登录引导、不得渲染内容（见 E12）。

**大厅页的特殊性**：这是唯一对 S0 开放的页面，因此它内部要维护两套渲染模式——匿名模式只渲染 10 条摘要卡片、隐藏筛选 Tab 与搜索框、不展示评论数之外的操作入口；登录后重载为完整模式。

## 三、异常提示与处理

### 3.1 错误码约定

| 错误码 | HTTP 类比 | 含义 | 可恢复 |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | 未授权 / 未建档 / 会话失效 | ✅ 重新登录 |
| `PROFILE_INCOMPLETE` | 403 | 已登录但资料不全 | ✅ 完善资料 |
| `ACCOUNT_BANNED` | 403 | 账号被封禁 | ❌ 申诉 |
| `ACCOUNT_DISABLED` | 403 | 账号停用 / 注销中 | ❌ 联系客服 |
| `RISK_REJECTED` | 403 | 风控命中（异常设备/频率） | ⏳ 稍后重试 |
| `FORBIDDEN` | 403 | 内容级越权（非本人/非接单人） | ❌ |
| `STATUS_CONFLICT` | 409 | 业务状态冲突（任务已被接走） | ⏳ 刷新后重试 |
| `NICKNAME_INVALID` | 400 | 昵称不合规（2–20 字 / 纯数字 / 控制字符） | ✅ 改一个 |
| `NICKNAME_TAKEN` | 409 | 昵称已被占用（不区分大小写） | ✅ 换一个 |
| `NICKNAME_CHANGE_USED` | 409 | 昵称修改机会已用完 | ❌ 不可恢复 |
| `CONTENT_RISK` | 422 | 内容安全检测未通过 | ✅ 修改后重试 |

### 3.2 场景 × 提示文案 × 系统处理

| # | 场景 | 触发条件 | 用户提示文案（原文） | 系统处理 |
|---|---|---|---|---|
| E1 | **首次进入未授权** | 冷启动无档案，或主动退出后进入 | 大厅顶部引导条：**「登录后可查看任务详情、发布和接单」** + 按钮「微信一键登录」 | 正常加载大厅，仅渲染 10 条摘要卡片；隐藏筛选 Tab、搜索框、发布悬浮按钮改为登录引导；不请求其它任何接口 |
| E1b | **匿名点击任务卡片** | S0 状态点击列表项 | 弹窗：**标题**「登录后才能查看任务详情」<br>**正文**：确认身份后即可查看完整内容并接单，我们只获取你的微信标识。<br>**按钮**：微信一键登录 / 再看看 | 不跳转详情、不发 `task.detail`；登录成功后自动进入该任务详情 |
| E1c | **匿名切换筛选 / 搜索** | S0 点击「进行中」「已完成」或搜索框 | 轻提示：「登录后可筛选任务」 | 不发请求；筛选 Tab 对 S0 置灰或点击即引导登录 |
| E1d | **匿名点击发布 / 评论 / 点赞** | S0 触发任何写操作入口 | 同 E1b 弹窗（文案按场景微调：发布/评论/点赞） | 拦截操作，不发起云函数调用 |
| E2 | **用户拒绝授权** | 点击登录后系统授权弹窗被拒绝 | 轻提示：「未完成登录，暂时无法使用」 | 停留 S0，不重复弹窗；本次会话不再自动拉起 |
| E3 | **授权过程网络/系统失败** | 建档接口超时或返回非业务错误 | 轻提示：「登录失败，请检查网络后重试」+ 重试按钮 | 停留 S0；连续 3 次失败后提示「稍后再试」，并记录错误日志 |
| E4 | **服务端建档失败** | 云环境异常、数据库不可用 | 弹窗：「服务暂时不可用，请稍后再试」 | 停留 S0；禁止降级为「本地假登录」 |
| E5 | **资料不全** | 已建档但缺昵称或头像 | 页面提示：「完善头像和昵称后即可发布任务」+ 去完善 | 进入 S3；只读可用，写操作在点击时统一拦截到资料页 |
| E6 | **账号被封禁** | 请求返回 `ACCOUNT_BANNED` | 全屏页：「账号已被封禁」<br>正文：原因分类 + 处理时间 + 「如有疑问可申诉」 | 清本地登录态；拦截全部业务页；仅留受限页 |
| E7 | **账号停用/注销中** | 返回 `ACCOUNT_DISABLED` | 全屏页：「账号已停用」<br>正文：如需恢复请联系客服 | 同上 |
| E8 | **会话失效** | openid 与档案不匹配 / 档案被删 | 轻提示：「登录状态已失效，请重新登录」 | 清本地态 → S0，自动或手动重新登录一次 |
| E9 | **风控拦截** | 请求频率、设备、内容风险命中 | 轻提示：「操作过于频繁，请稍后再试」 | 不失效登录态，仅拒绝本次请求 |
| E10 | **内容级越权** | 非 owner 尝试删改、非接单人提交 | 轻提示：「你没有权限操作这条内容」 | 不失效登录态，记录越权日志 |
| E11 | **主动退出** | 用户在「我的」点退出 | 二次确认：「退出后需要重新登录才能使用」 | 清本地态 → S0，不调用任何服务端注销接口（微信身份仍在） |
| E12 | **未授权直达内页** | 通过分享卡片 / 扫码进入任务详情、话题等非大厅页 | 同 E1b 弹窗（该页不渲染内容，仅展示登录引导） | 记录待跳转路由（含参数），登录成功后**回到原目标页**；不得先渲染内容再遮罩 |

### 3.3 文案规则

1. 不暴露内部信息：不得出现 openid、数据库字段名、云函数名、错误堆栈。
2. 区分「你的问题」与「我们的问题」：网络/系统故障一律说「服务暂时不可用」，不暗示用户操作错误。
3. 封禁类文案必须给出**可申诉路径**，不得只写「无法使用」。
4. 同一错误码只对应一套文案，由统一错误处理层输出，**不允许每个页面自己拼**。
5. **`wx.showModal` 的 `confirmText` / `cancelText` 最多 4 个字符**。超过会导致调用直接 fail——不弹窗、界面无报错，表现为「点了没反应」。所以确认按钮统一用「微信登录」「知道了」「确定」这类 2–4 字文案，长文案放 `title` 或 `content`。
6. 任何 `showModal` 必须提供 `fail` 回调并 `console.error`，禁止 `fail: () => {}` 静默吞错。
7. 显式登录按钮（文案本身就是「微信一键登录」的）**直接执行登录**，不再弹确认框；只有「拦截用户原本想做的操作」时才弹确认。

## 四、操作入口校验清单

### 4.0 服务端统一校验管线（每个业务接口按序执行）

| 步骤 | 校验内容 | 不通过返回 | 说明 |
|---|---|---|---|
| V1 | 取 `OPENID`，为空则拒 | `UNAUTHORIZED` | 实际几乎不触发，保留兜底 |
| V2 | 按 openid 查档案，不存在则拒 | `UNAUTHORIZED` | **这一步替代了「是否登录」判断** |
| V3 | 档案 `status` 是否为 active | `ACCOUNT_BANNED` / `ACCOUNT_DISABLED` | R3、R5 |
| V4 | 写操作校验 `profileComplete` | `PROFILE_INCOMPLETE` | 只读接口跳过 |
| V5 | 业务校验：存在性、归属、状态机 | `NOT_FOUND` / `FORBIDDEN` / `STATUS_CONFLICT` | R4 |
| V6 | 执行 | — | — |

**管线要求**：V2–V4 必须在**每个**业务云函数入口统一执行，不允许各函数自行实现、也不允许遗漏。任何新增接口默认走完整管线。

**唯一例外（匿名放行分支）**：`task.list` 允许跳过 V2 之后直接走「匿名分支」。该分支必须按下述规则收口，不得复用登录用户的查询逻辑：

| 步骤 | 匿名分支行为 |
|---|---|
| A1 | 按 openid 查档案；**查到且 active** → 走正常登录分支，忽略后面的匿名限制 |
| A2 | 查不到档案 / 状态为 unauthorized → 进入匿名分支 |
| A3 | 强制 `status = pending`，忽略入参中的 `status` |
| A4 | 强制 `keyword = 空`，忽略入参中的 `keyword` |
| A5 | 强制 `skip = 0`、`limit = 10`，忽略 `page` / `pageSize` |
| A6 | 按字段白名单裁剪返回值（L4），其余字段一律剔除 |
| A7 | `hasMore` 恒返回 `false` |

除 `task.list` 外，**没有任何接口允许匿名调用**。新增接口若声称需要匿名放行，必须单独评审并写入本清单。

### 4.2 前后端一致性要求

| 要求 | 说明 |
|---|---|
| C1 | 同一入口，前端拦截条件与服务端校验条件必须**逐条对应**。前端因 `profileComplete=false` 拦截，服务端也必须因同一原因拒绝。 |

| C5 | 每个新增接口必须同时更新本清单，否则视为未完成。 |
